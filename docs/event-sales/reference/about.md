# About this guide

This handbook explains PBG’s custom **Event Sales** module in Salesforce. It is written for sellers, their managers, and the administrators supporting the workflow.

## How it is organized

The guide follows the handbook approach of the [Partnerships CRM documentation](https://agilitek-solutions.gitbook.io/partnerships-crm-agilitek): start with customers and opportunities, then move through sales, agreements, delivery, and administration. Event Sales instructions were written for PBG’s implementation; Partnership-specific products, pricing, and fulfillment features are not assumed to apply here.

## What was verified

On **October 6, 2026**, the guide was checked against:

- Live Event Sales Home, the opportunity creation form, and agreement workspace controls.
- Deployed Event Sales and Special Event Agreement components and services.
- Live sales stages, fiscal configuration, and active agreement-template availability.
- The latest Event Agreement repair/validation chat and its current release state.

The agreement workflow is still receiving improvements. [Recent changes](./recent-changes) identifies the latest verified behavior and the remaining end-to-end verification boundary.

## Visuals and examples

Live screenshots show empty personal views, blank forms, or cropped generic controls. Customer names, addresses, contract amounts, internal record URLs, and private implementation evidence are excluded. Worked examples and the interactive practice exercise are fictional and are labeled accordingly.

The guide is text-first and does not require a voice-over video. Images have descriptive alternative text. Use the browser’s Print action for a printable version of an individual article.

## Suggest a correction

Use **Suggest an improvement** at the bottom of an article to propose a documentation change in GitHub. For a private customer problem, use the internal support channel instead.

Maintainers should verify a changed workflow in Salesforce, update the affected steps and visuals, update Recent changes, and run the build/link checks before publishing. The repository automatically publishes approved changes on its main branch to GitHub Pages.
